Một frame chạy thế nào

Thứ tự dưới đây đúng như trong code.

  1. Input đến theo sự kiện. KeyboardInput, VirtualJoystick ghi vào InputState khi có phím hoặc chạm, không ai phải hỏi vòng mỗi frame.
  2. GameManager.update(dt) chỉ chạy khi state là Playing. Nó cắt frame thành các bước tối đa 50 ms, frame dài hơn 250 ms thì bỏ phần thừa.
  3. Mỗi bước gọi BattleWorld.step: player di chuyển → súng player → BossBrain (phase, chọn move/shot, chạy chúng) → đạn hai bên bay và bị xoá khi chạm tường → xét va chạm → trả về BattleOutcome.
  4. GameManager phát sự kiện HP, phase, trúng đạn chỉ khi giá trị đổi; boss chết thì xoá hết đạn rồi phát GAME_OVER.
  5. Trong lateUpdate, các view chép model lên node: PlayerView, BossView, hai BulletLayerView, CameraFollow.
  6. UI (thanh máu, nhãn phase, bảng Game Over) chỉ chạy khi nhận sự kiện.
// controller/GameManager.ts
private simulateFrame(dt: number, world: BattleWorld): BattleOutcome {
    // NOTE: frames longer than MAX_FRAME_TIME (tab switch, debugger) are cut, not fast-forwarded.
    let remaining = Math.min(dt, GameConfig.FRAME.MAX_FRAME_TIME);
    let outcome = BattleOutcome.None;
    while (remaining > 0 && outcome === BattleOutcome.None) {
        const step = Math.min(remaining, GameConfig.FRAME.MAX_DT);
        outcome = world.step(step, this._input);
        remaining -= step;
    }
    return outcome;
}
Vì sao sub-step: máy yếu chạy 15 fps thì dt ≈ 0.066 s. Nếu bước một lần, đạn player (900 px/s) nhảy 60 px mỗi bước và có thể "xuyên" qua mục tiêu. Cắt thành bước ≤ 50 ms vừa giữ đúng tốc độ thật, vừa giữ va chạm chính xác.

BulletStoremodel/BulletStore.ts · 121 dòngmodel

Lưu toàn bộ đạn của một phe trong 4 mảng Float32Array cố định (x, y, vx, vy). Đạn đang sống nằm ở chỉ số [0, count). Không có object nào cho từng viên đạn.

/** Swap-remove: the last bullet takes the freed slot. */
private removeAt(index: number): void {
    // PERF: O(1) instead of shifting every later bullet (order does not matter for bullets).
    const last = this._count - 1;
    if (index !== last) {
        this.x[index] = this.x[last];
        this.y[index] = this.y[last];
        this.vx[index] = this.vx[last];
        this.vy[index] = this.vy[last];
    }
    this._count = last;
}
step(dt: number, bounds: ArenaBounds): void {
    // NOTE: loop backwards: removeAt moves the last bullet into slot i, and that bullet was
    // already processed, so nothing is skipped or moved twice.
    for (let i = this._count - 1; i >= 0; i--) {
        this.x[i] += this.vx[i] * dt;
        this.y[i] += this.vy[i] * dt;
        if (bounds.touchesWall(this.x[i], this.y[i], this.radius)) {
            this.removeAt(i);
        }
    }
}
Vì sao: không tạo object khi bắn, không rác cho GC, dữ liệu nằm liền nhau trong bộ nhớ nên duyệt nhanh. clear() chỉ đặt count = 0, đó là cách "xoá hết đạn ngay lập tức" khi boss chết.
Hỏi: vì sao duyệt ngược từ cuối mảng?
Vì removeAt(i) lấy viên cuối mảng đặt vào chỗ i. Viên cuối đó đã được xử lý rồi (đi ngược), nên không viên nào bị bỏ sót hay xử lý hai lần.

private emitHealthChange(health: Health, lastHp: number, hpEvent: string, hitEvent: string): number {
    const hp = health.current;
    if (hp === lastHp) { return lastHp; }       // PERF: no event when nothing changed
    if (hp < lastHp) { EventBus.emit(hitEvent); }
    EventBus.emit(hpEvent, hp, health.max);
    return hp;
}

Cách hiểu "thời điểm kích hoạt": hướng được khoá ngay khi bắt đầu windup, nên ánh nháy trắng báo trước một hướng cố định và player có thể né sang ngang. Nếu ngắm lúc hết windup thì boss gần như luôn trúng, không công bằng.
Vì sao kẹp điểm ngắm: player nhỏ hơn boss nên đứng sát tường được hơn. Ngắm thẳng vào player thì mọi cú dash đâm vào tường và boss bị kẹt. Kẹp điểm ngắm vào vùng tâm boss tới được thì boss lướt dọc tường.

Một class phục vụ mọi kiểu quạt; Normal và Crazy chỉ khác số liệu trong config.

constructor(config: FanShotConfig) {
    this.config = config;
    const spread = degToRad(config.SPREAD_DEG);
    // angle_i = base - spread/2 + spread * i / (count - 1); one bullet would divide by zero.
    const hasSpread = config.COUNT > 1;
    this.firstOffset = hasSpread ? -spread / 2 : 0;
    this.angleStep = hasSpread ? spread / (config.COUNT - 1) : 0;
}

private fireVolley(origin: Point, target: Point, emitter: IBulletEmitter): void {
    // PERF: atan2 once per volley, not per frame.
    const baseAngle = Math.atan2(target.y - origin.y, target.x - origin.x);
    const speed = this.config.SPEED;
    for (let i = 0; i < this.config.COUNT; i++) {
        const angle = baseAngle + this.firstOffset + this.angleStep * i;
        emitter.spawn(origin.x, origin.y, Math.cos(angle) * speed, Math.sin(angle) * speed);
    }
}

export function circleOverlapsBox(cx: number, cy: number, r: number, boxX: number, boxY: number, halfSize: number): boolean {
    // The point of the square closest to the circle centre; overlap if that point is inside the circle.
    const nearestX = clamp(cx, boxX - halfSize, boxX + halfSize);
    const nearestY = clamp(cy, boxY - halfSize, boxY + halfSize);
    const dx = cx - nearestX;
    const dy = cy - nearestY;
    return dx * dx + dy * dy < r * r;   // PERF: squared distance, no Math.sqrt
}

private move(dt: number, dirX: number, dirY: number, bounds: ArenaBounds): void {
    const lengthSqr = dirX * dirX + dirY * dirY;
    if (lengthSqr === 0) { return; }
    // only shrink, never grow: a diagonal key press is scaled to 1, a half-tilted stick keeps its slower speed.
    if (lengthSqr > 1) {
        const scale = 1 / Math.sqrt(lengthSqr);
        dirX *= scale;
        dirY *= scale;
    }
    const distance = PLAYER.SPEED * dt;
    this.moveClamped(dirX * distance, dirY * distance, bounds);
}
  • Bất tử = sau khi trúng (1 s, nhấp nháy) hoặc đang dash. Trúng đòn chí mạng thì không bật bất tử, để player chết không nhấp nháy sau màn DEFEAT.
  • Dash: hướng là hướng di chuyển gần nhất, luôn chuẩn hoá; bước cuối chỉ dùng phần thời gian còn lại nên quãng đường đúng 1100 × 0.15 = 165 px.
  • Súng: tầm so bằng bình phương (AUTO_AIM_RANGE_SQR tính sẵn một lần), một sqrt mỗi phát bắn, không phải mỗi frame; khoảng cách 0 thì bỏ qua để không chia cho 0.
BulletLayerViewview/BulletLayerView.ts · 124 dòngview

Vẽ đạn của một phe. Giữ danh sách node "slot" tạo sẵn; mỗi frame bật count slot đầu, đặt vị trí theo mảng, tắt phần còn lại. Đây chính là pool: node tạo một lần, chỉ bật tắt, không bao giờ huỷ khi đang chơi.

protected lateUpdate(): void {
    const store = this.store;
    if (!store) { return; }
    const count = store.count;
    this.ensureSlots(count);
    const xs = store.x;
    const ys = store.y;
    for (let i = 0; i < count; i++) {
        this.slots[i].setPosition(xs[i], ys[i], 0);
    }
    this.updateVisibleCount(count);
}

private updateVisibleCount(count: number): void {
    // PERF: changing node.active walks the node's components, so never set it when unchanged.
    for (let i = this.shownCount; i < count; i++) { this.slots[i].active = true; }
    for (let i = count; i < this.shownCount; i++) { this.slots[i].active = false; }
    this.shownCount = count;
}
Vì sao không dùng NodePool get/put: mỗi lần put/get là gỡ node khỏi cha và gắn lại (tốn duyệt mảng con). Bật tắt active trên slot cố định rẻ hơn, và vì mọi viên đạn trông giống nhau nên không cần biết node nào là viên nào.

Gần như không: tạo sẵn 32 slot đạn player và 200 slot đạn boss lúc load. Chỉ khi số đạn vượt mức đó mới tạo thêm, tối đa bằng sức chứa của store (400), và chỉ một lần.

model/ không import cc, một update duy nhất, view chỉ chép dữ liệu. Luật chơi chạy và test được ngoài Cocos.

Đạn dạng dữ liệu, không rác

Typed array cố định, swap-remove, slot node tạo sẵn: không cấp phát trong vòng lặp nóng.

MẠNH

Mở rộng boss bằng dữ liệu

Interface + factory + bảng phase; thiếu entry là lỗi biên dịch.

CẦN BIẾT

Chưa có unit test

Model thuần TS rất dễ test nhưng repo chưa có test nào.

Hướng cải thiện: viết test cho Collision, góc của FanShot và chuyển phase của BossBrain, vì chúng không phụ thuộc engine.

CẦN BIẾT

Ngẫu nhiên không có seed

Math.random được dùng trực tiếp, nên không tái hiện được đúng một trận để debug hay replay.

Cách sửa: truyền một bộ sinh số ngẫu nhiên có seed vào BossBrain.

CẦN BIẾT

Va chạm rời rạc, an toàn nhờ sub-step

Không dùng va chạm quét (swept). Hiện an toàn vì bước tối đa 50 ms; nếu đạn player nhanh hơn khoảng 2700 px/s thì có thể xuyên qua boss.

CẦN BIẾT

Scene được sinh bằng script

Main.scene do tools/gen-bullethell-scene.js tạo, chưa từng được editor lưu lại.

Hướng cải thiện: mở scene trong editor 3.7.4 và lưu lại một lần để scene có định dạng chuẩn của editor.
